# Vedetta v0.1.0-beta.2 — Windows sensor

> Follows [v0.1.0-beta.1](v0.1.0-beta.1.md). The headline is a **native Windows
> sensor**; Core, the macOS/Linux sensors, and everything from beta.1 are unchanged.

## New: native Windows sensor

A first-class sensor for **Windows 11, Windows 10 22H2, and Windows Server 2022** —
shipped as a single **driver-free** executable:

- **DNS capture** via the `Microsoft-Windows-DNS-Client` **ETW** provider — no Npcap,
  no nmap, no cgo. It reads the OS resolver's own queries/responses.
- **Device discovery** via native `IcmpSendEcho` sweeps + `arp -a`, unioned with the
  ARP neighbor table so firewalled hosts that drop ICMP are still found.
- Runs as a **LocalSystem Windows service**; the auth token lives in
  `%ProgramData%\Vedetta`, ACL-restricted to SYSTEM + Administrators.
- Installs with `sensor/deploy/install.ps1` (run as Administrator).

**Scope (v1):** capture is **host-scoped** — it sees the DNS of the machine the sensor
runs on, not other devices' traffic. Segment-wide L2 capture (optional Npcap) and deep
`nmap` scans remain a future, never-required opt-in tier.

The release ships a checksummed `vedetta-sensor_windows_amd64.zip` alongside the Linux
assets; `install.ps1` verifies it against `checksums.txt`.

## Security & robustness fixes (independent review)

This release closes findings from an independent security review of the Windows work:

- **Installer works for prereleases.** `install.ps1` no longer relies on GitHub's
  `/releases/latest` (which excludes prereleases); it resolves the newest release
  carrying the Windows asset, and accepts an explicit `-Tag`.
- **Enrollment secret never sits in the service config.** The one-time code is spent in
  a one-shot elevated enrollment step (passed via the environment, not a command line);
  the long-running service is created with **no** code in its `ImagePath`, so a standard
  user cannot recover it via `sc qc`.
- **Correct Windows service lifecycle.** The process connects to the Service Control
  Manager immediately and does registration/scanning in the background (reporting
  `Running` while retrying), so a Core that is unreachable at boot no longer risks
  Error 1053. Stop/Shutdown is bounded: cancellation threads through registration and
  the Core HTTP calls, the scan loop checks for it between targets, and a hard 18s cap in
  the service handler backstops any in-flight native scan (a single sweep is not itself
  interrupted mid-flight).
- **Accurate DNS attribution.** Host-scoped DNS is stamped with the sensor host's
  LAN-scoped IP, refreshed so DHCP/VPN/Wi-Fi changes are tracked.
- **Diagnosable service.** Windows service logs go to an ACL-restricted, size-capped
  `%ProgramData%\Vedetta\sensor.log` (a service has no usable stderr).
- **No stray pcap on Windows.** Passive discovery (pcap/Npcap) is compiled out of the
  Windows build; the binary links **zero** pcap symbols. CI now builds, vets, tests, and
  binary-scans the Windows sensor on `windows-latest`.
- Oversized scan targets (larger than a /22) are rejected rather than silently
  truncated; the sensor reports its real build version to Core.

## Install

The beta.2 installer is retained only as historical release context. Its enrollment
interface put the one-time code in process arguments and has been superseded. For a
new installation, use the pinned beta.4-or-newer flow in the
[current README](../../README.md#2-deploy-a-sensor); do not reuse the beta.2 command.

The macOS/Linux sensor itself is unchanged from beta.1; `install.sh` now selects the
newest published (pre)release asset (GitHub's `/releases/latest` excludes prereleases),
so it installs this tagged, checksum-verified build instead of falling back to a source
build of `main`.

## What "beta" means

Same posture as beta.1 (self-hosted, LAN-first, still hardening). Windows-specific: v1
is **host-scoped** (this machine's DNS), and apps that use DoH/DoT to bypass the OS
resolver are not visible to ETW capture.
